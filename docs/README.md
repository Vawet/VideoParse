# docs

功能变更的意图记录。按需加载，不进入常驻上下文。

产品定位仍在 `PRODUCT.md`。接口、数据结构和当前行为以代码、测试为准，不在这里手抄一份。

## 何时写

改了可观察行为时，在本目录新增或更新一篇，和代码放在同一次改动里。包括接口、Agent 行为、前端交互、默认配置。

纯重构、注释、不改变行为的修复不用写。只讨论、还没改代码时，若方案已经写出，也落一篇，并标明「未实现」。

## 一篇里写什么

- 状态：`未实现` / `已实现未验证` / `已验证`（写明验证方式和日期）
- 目标、现状、决定、非目标、验收
- 来源：哪次讨论或哪段代码。区分已确认、方案、未决

不记录密钥、不粘贴 `.env`、不把一次运行观察写成普遍事实。

## 文件名

`docs/<主题>.md`，正文用中文。一个功能一篇；后续改动更新原文，不另起平行文档。
