# 聊天上下文长度

状态：历史滑动窗口，以及问答循环里只保留最近两条工具结果，已实现，2026-10-30 由 `test_agent_offline.py` 离线验证。摘要与超长后自动缩小重试仍未实现。来源：2026-10-30 讨论，对照 `后端/app/agent/loop.py`。

## 目标

历史或单次工具结果过长时，问答仍能返回，并且最新一轮问题和回答被完整保留。

## 已确认

- 拼进模型前，`fit_history` 按轮次从新到旧保留，预算是 `CHAT_HISTORY_CHAR_BUDGET`（默认 12000 字符）。最近一轮历史超预算时仍整段保留，不从句子中间切开。当前问题另附，不参与裁剪。
- 返回给前端的 `history` 仍是完整历史加本轮，不在前端侧丢轮次。历史仍由前端持有。
- 返回的 `history` 只追加本轮 user / assistant 最终文本。工具调用和工具结果不进入历史。
- 单次循环里，`run_tool` 把超过 3000 字符的工具输出收成 `preview`。问答循环另外只保留最近两条工具结果原文，更早的换成占位。解析循环不裁这批结果。
- 问答步数用尽时的返回方式见 `agent-architecture.md`。
- 最近一轮本身超预算时仍会整段送出，模型窗口仍可能被撑满。超长后的自动缩小重试还没有。

## 未实现

1. 放不下的早期轮次用一次模型调用压成摘要，并随 `history` 交回前端。摘要里要保留结论对应的时间戳。
2. 若仍因上下文超长失败，缩小窗口重试一次；再失败则返回明确错误。最近一轮历史超预算时仍会整段送出。

## 非目标

- 不把工具轨迹写入长期历史。
- 不在本篇维护接口字段清单。

## 验收

- 已覆盖：更早轮次超出预算时不再送进模型；最近一轮超预算仍整段保留；返回的 `history` 仍含更早轮次；问答循环里早于最近两条的工具结果被换成占位。
- 未覆盖：超长失败后的自动缩小重试。
