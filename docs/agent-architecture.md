# Agent 架构（多角色）

状态：多角色分层未实现。问答循环的步数用尽、重复调用提前停止、原问题回放到末尾、只保留最近两条工具结果，已在 2026-10-30 由 `test_agent_offline.py` 离线验证。真实模型评测尚未重跑，所以还没有步数和引用通过率的对照数字。来源：2026-10-27 讨论；2026-10-30 对照 Anthropic《Building effective agents》与 ReAct 的失败模式，决定先收紧问答循环，不加 Planner。

## 目标

架构上能指出规划、分工、反思、记忆、路由，并且每一环出现在事件流里。解析仍走确定性流水线。

## 已确认

- 解析默认 `pipeline`，失败或校验有问题才把修复交给 Agent。解析循环允许同一工具重试。
- 问答在代码里做时间戳引用校验，无效且未声明「未提及」时追问一次。
- 工具按 `analyze` / `chat` / `course` 分组。
- 问答循环（`chat` / `course`）：相同工具、相同参数不执行第二次，再向模型要一次不带工具的回答；从第二步起把原问题放回上下文末尾；只保留最近两条工具结果，更早的换成占位。
- 步数用尽时返回最后一段助手正文并标注。没有正文时写明停在哪个工具。解析路径仍抛出 `AgentStepLimit`，由 `analyze_video` 捕获后 `finish`。
- `python -m app.tests.eval.run_eval` 的汇总里，除引用通过率、命中率、拒答率外，还有 `mean_steps`、`mean_tool_calls`、`repeated_tool_calls`。这次没有跑真实模型。

## 方案（推荐，未授权实现）

不引入 LangGraph / AutoGen。在现有 `run_agent` 外分层：

1. Router：区分问答、整课问答、出题、复习、验证。
2. Planner：只对跨视频、对比、多问触发，输出子任务；简单问题直接走现有循环。
3. Executor：复用 `run_agent`，子任务独立消息和步数上限；无依赖的子任务并行。
4. Critic：保留现有引用校验，其上加一轮有界审阅。
5. 上下文压缩：历史窗口见 `chat-context.md`。问答循环内只保留最近两条工具结果，已实现。
6. 问答步数用尽时返回已有正文并标注。已实现。
7. `emit` 增加 `plan`、`delegate`、`critique`，不删除已有事件类型。未实现。

配置开关 `AGENT_ARCH=simple|multi`，默认 `simple`。`Workspace` 仍是唯一写入方，子 Executor 只读共享。

## 非目标

- 不替换解析流水线。
- 不降低「答案要么有有效时间戳，要么明确未提及」这条代码保证。
- 不用新框架重写 `loop.py`。

## 未决

- 复杂问题评测集尚未补充。多角色会增加调用次数、延迟和费用。

## 验收（若进入实现）

- 默认 `simple` 时，现有离线问答测试行为不变。
- 评测记录每次问答的调用次数与耗时。
- 跨视频问题集上，`multi` 的答案覆盖度高于 `simple`；否则结构只剩展示价值，应停在开关后而不是替换默认路径。
